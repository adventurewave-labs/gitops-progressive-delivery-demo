# What this demo is — and isn't

A quick, honest breakdown so you know exactly what you're looking at.

## TL;DR

| | |
|---|---|
| **The web app** | ✅ **Real.** A working Next.js 16 + TypeScript app. Builds, lints clean, ships in Docker, runs anywhere. |
| **The GitOps pipeline it depicts** | 🎭 **Simulated.** No real cluster, no real Argo CD, no real Prometheus, no real K8sGPT. All visuals are driven by a client-side state machine. |

---

## What's real

The application itself is a fully functional piece of software:

- **Next.js 16 + TypeScript 5 + Tailwind CSS 4 + shadcn/ui** — production-grade stack.
- **Builds and lints clean** — ESLint passes with zero errors, `next build` produces a working standalone server.
- **Dockerized** — multi-stage `Dockerfile` on `node:20-alpine`, runs as non-root, has a `HEALTHCHECK`. `docker build . && docker run -p 3000:3000` works on any machine with Docker.
- **CI passes** — GitHub Actions runs lint + Docker build + container smoke test on every push.
- **UAT passes** — 31 automated checks against the running app validate every state, traffic split, SLO badge flip, terminal stream line, reset behavior, and mobile responsiveness.
- **Codespaces-ready** — `.devcontainer/devcontainer.json` auto-installs Bun, forwards port 3000, opens the preview in your browser.

You can fork it, deploy it to Vercel/Netlify/Fly/Codespaces, modify the styling, add new states, wire in real backend integrations, ship it as an internal training tool — whatever you want. The code is real.

---

## What's simulated

The *content* of the demo — the GitOps pipeline behavior — is a visualization, not a live integration. Concretely:

| Element | What you see | What's actually happening |
|---------|--------------|---------------------------|
| **Argo CD "sync"** | Pulsing arrow from Git → cluster, "Applying" → "Synced" badge flip | A `useState` toggle driven by `setTimeout` in `src/app/page.tsx` |
| **Argo Rollouts traffic shift** | Animated horizontal pipe showing 80/20 → 50/50 → 100/0 | A `motion.div` whose `width` animates based on `TRAFFIC_SPLIT[state]` in `src/lib/demo-state.ts` |
| **Prometheus metrics** | Two line charts showing error rate spiking to 15% and p99 latency to 2000ms | Synthetic time-series with jitter, generated by a `setInterval` in `src/app/page.tsx` |
| **K8sGPT terminal stream** | 9 diagnosis lines streaming into a mac-style terminal with a blinking cursor | A pre-written array in `src/lib/demo-state.ts` (`K8SGPT_STREAM`), revealed one line per 700ms by a `setInterval` |
| **The "anomaly"** | SLO badge flips to `SLO VIOLATED`, charts spike | Hardcoded — `METRICS.anomaly = { errorRate: 15, p99Latency: 2000 }` |

There is **no**:
- Kubernetes cluster
- `kubectl` connection
- Argo CD instance or API call
- Argo Rollouts controller
- Prometheus scrape
- K8sGPT process or LLM call
- Real canary traffic
- Real Git push

## Why this is fine

The demo's purpose is **visual storytelling** — to show platform engineers, SREs, and DevOps leaders what a GitOps-driven progressive delivery pipeline *looks like* and *feels like* when an AI SRE gets involved. It's an educational / sales / training artifact, not a reference implementation.

Building a real version would require:
- A real Kubernetes cluster (kind, minikube, GKE, EKS, AKS)
- Argo CD installed and connected to a real Git repo
- Argo Rollouts installed with a real `Rollout` CRD
- Prometheus scraping real pods
- K8sGPT installed with real OpenAI/Azure keys
- A real `payments-api` Docker image with a deliberately-broken v2.4

That's a 2-4 hour setup with real cloud costs — inappropriate for a "click and watch" demo. The simulation gives you the same narrative in 20 seconds, for free, in any environment.

## Want to make it real?

This codebase is a great **scaffold** for a real integration. If you want to graduate from "demo" to "live pipeline viewer", here's a roadmap:

1. **Replace the state machine with real cluster polling.** In `src/app/page.tsx`, swap `scheduleAdvance(state)` for a `setInterval` that hits `/api/cluster-status` — a Next.js route handler that calls `kubectl` (or the Argo CD API) and returns the current Rollout phase.
2. **Replace the synthetic Prometheus series with real PromQL queries.** In `PrometheusMetricsCard.tsx`, swap the `setInterval` that generates jitter for a `fetch('/api/metrics?query=http_error_rate')` that proxies to your real Prometheus instance.
3. **Replace the K8sGPT script stream with the real K8sGPT CLI.** Spawn `k8sgpt analyze --json` as a child process from a route handler and stream the results back via WebSocket (the project already has a `mini-services/` pattern for this).
4. **Add a "live mode" toggle.** Keep the simulated state machine as a "demo mode" (default) so the app still works for first-time visitors with no cluster, but add a "Connect cluster" flow that switches to live mode.

Each of those is a 1-2 day project. The architecture supports it cleanly because the simulation logic is **fully isolated** in `src/lib/demo-state.ts` — replace that file's exports with live data and the UI components don't need to change.
